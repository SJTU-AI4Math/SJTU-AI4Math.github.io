Section 1 -- 依赖类型
Remark 1.1 -- 依值即 λ\lambdaλ-抽象

考虑函数 f:N→Nf : \N\to\Nf:N→N。我们断言：“函数 fff 的返回值依赖于所应用的参数”。

在这一语句中，fff 作为 N→N\N\to\NN→N 类型的函数对象是独立的，而 fff 作为 N\NN 类型的自然数对象是依值的。

故而言一个对象“依值”，即言其经过了 λ\lambdaλ-抽象。

Remark 1.2 -- “依值”的多态性

在 STLC 中，一切实体被在元理论中分为两大类别（Sort）：项（Terms）与类型（Types）。

通过 λ\lambdaλ-抽象，项可以依赖项，但类型始终简单。

在数学与代码实践中，会产生复杂的依赖关系：

  1. 项依赖类型；
  2. 类型依赖项；
  3. 类型依赖类型。

Subsection 3.1 -- 归纳类型信息
Definition 3.1.1 -- Inductive Declarations and Generated Recursors

An inductive declaration gives Lean the following data:

  1. a new family name I, its universe, parameters, and indices;
  2. a finite list of constructors, each with its complete dependent-function type;
  3. for every constructor, the arguments it accepts and the indices of the I-object it builds.

Lean accepts the declaration only when the surrounding context is well formed, every constructor type is well typed, every constructor result is headed by the new family I with the declared parameters in the required positions, and every recursive occurrence of I is strictly positive. Informally, a constructor may contain smaller I-objects, but it may not consume an I-object as the input of a nested function. List I is an accepted strictly-positive container; (I → A) → I is rejected. Parameters stay fixed across recursive occurrences, whereas indices may change according to the constructor result.

From an accepted declaration Lean mechanically generates a recursor. For direct recursion in a family I p̄ ī, the simple schema asks for:

  • a motive motive : (ī : indices) → I p̄ ī → Sort v describing what is to be produced for every possible input;
  • one method for each constructor;
  • in a constructor method, one induction hypothesis for every argument whose type is directly headed by I.

For a directly recursive constructor c : (ā : Δ) → I p̄ t̄, its method returns motive t̄ (c ā). If some aⱼ is directly recursive, the method additionally receives the recursively computed result for aⱼ. Applying the recursor to the constructor then selects that method:

I.rec motive methods (c ā recursiveArgs)
  ≡ method_c ā recursiveArgs (I.rec motive methods recursiveArgs)

Nested recursion through an accepted strictly-positive container needs extra bookkeeping. For an argument such as List I or Option I, Lean may generate an auxiliary motive for the container and methods for its constructors, threading the I-induction hypotheses through that traversal. It is therefore not merely “one hypothesis for the whole container argument.” In this chapter, LinkedNode produces motive_1 for LinkedNode, motive_2 for Option LinkedNode, and methods for mk, none, and some. The direct-recursion schema above describes the common case; the generated recursor signature is the authority for nested and mutual recursion.

For natural numbers this becomes:

inductive Nat where
  | zero : Nat
  | succ : Nat → Nat

Lean generates the following recursor shape:

Nat.rec
  (motive : Nat → Sort u)
  (zero : motive Nat.zero)
  (succ : (n : Nat) → motive n → motive (Nat.succ n))
  (t : Nat) : motive t

and its computation rules are Nat.rec motive z s Nat.zero ≡ z and Nat.rec motive z s (Nat.succ n) ≡ s n (Nat.rec motive z s n). These constructor equations are ι-reduction. Pattern matching and structural recursive definitions are convenient syntax that Lean elaborates using the same constructor cases and recursive calls.

Subsection 3.2 -- 归纳类型实例
Definition 3.2.1 -- W-Types

Given A : Type and B : A → Type, W A B is the type of well-founded trees generated by one constructor.

universe u v

inductive W (shape : Type u) (position : shape → Type v) where
  | sup (a : shape) (children : position a → W shape position)

The constructor and recursor belong to this same definition: sup chooses a node shape and supplies one subtree for every position of that shape. Its recursor method receives a, children, and an induction hypothesis (i : position a) → motive (children i). On sup a children, the recursor computes by applying that method to a, children, and the recursively computed children.

Definition 3.2.2 -- Enumeration Types

An enumeration is one inductive definition with finitely many nullary constructors. The course keeps several instances side by side inside this concept; for example:

inductive Bool where
  | false | true

inductive Color where
  | red | green | blue

inductive Weekday where
  | monday | tuesday | wednesday | thursday
  | friday | saturday | sunday

Color.rec therefore asks for one result for red, one for green, and one for blue. It computes by selecting the matching result, e.g. Color.rec motive r g b Color.red ≡ r. Boolean and weekday enumerations have the same shape with two and seven branches respectively.

Definition 3.2.3 -- Natural Numbers

Natural numbers are one inductive definition with a base constructor and a recursive constructor.

inductive Nat where
  | zero : Nat
  | succ : Nat → Nat

Nat.rec contains the constructor cases in the same order: a value for zero, and a step taking n together with the recursively computed result for n. Hence it computes by rec zero ≡ base and rec (succ n) ≡ step n (rec n).

Definition 3.2.4 -- Lists

A list definition packages the type, both constructors, and their recursor together.

universe u

inductive List (α : Type u) where
  | nil : List α
  | cons : α → List α → List α

The nil method supplies the base result. The cons method receives the head, tail, and induction hypothesis for the tail. Consequently rec nil ≡ base and rec (cons x xs) ≡ step x xs (rec xs).

Definition 3.2.5 -- Sum Types

The sum type, its injections, and its eliminator are one concept.

universe u v

inductive Sum (α : Type u) (β : Type v) where
  | inl : α → Sum α β
  | inr : β → Sum α β

Its recursor asks how to handle an α and how to handle a β; it computes by selecting the corresponding branch: rec (inl a) ≡ left a and rec (inr b) ≡ right b.

Definition 3.2.6 -- Product Types

The product type, pairing constructor, projections, and recursor are presented together.

universe u v

inductive Prod (α : Type u) (β : Type v) where
  | mk : α → β → Prod α β

Because there is one constructor, the recursor has one method taking both fields and computes as rec (mk a b) ≡ method a b. The standard structure additionally exposes the generated projections fst and snd.

Definition 3.2.7 -- Currying

Definition 3.2.8 -- Unit Type

The unit type has exactly one nullary constructor.

inductive Unit where
  | unit

Its recursor needs one result and always returns it: Unit.rec motive u Unit.unit ≡ u.

Definition 3.2.9 -- Empty Type

The empty type has no constructors.

inductive Void

Accordingly its recursor asks for no constructor methods. Given an impossible x : Void, Void.rec motive x can produce a result in any motive; there is no constructor computation case because no Void value can be built.

Definition 3.2.10 -- Binary Trees

A binary tree is one definition whose node constructor contains two recursive arguments.

universe u

inductive BinTree (α : Type u) where
  | leaf : α → BinTree α
  | node : BinTree α → BinTree α → BinTree α

The leaf method receives its label. The node method receives both subtrees and one induction hypothesis for each subtree, so rec (node l r) computes from rec l and rec r.

Definition 3.2.11 -- Vectors

A vector is one inductive family indexed by length.

universe u

inductive Vector (α : Type u) : Nat → Type u where
  | nil : Vector α 0
  | cons {n : Nat} : α → Vector α n → Vector α (n + 1)

Its motive depends on both the length and the vector. The nil method proves the motive at length zero; the cons method receives n, the head, the tail, and the induction hypothesis at index n, and must produce the motive at n + 1. This index refinement is why a head function for Vector α (n + 1) needs no impossible nil branch.

Indices compute, but they are not magically identified by arbitrary theorems: for variable m,n, Vector α (m+n) and Vector α (n+m) are generally not definitionally equal. Using commutativity requires explicit rewriting or transport.

Definition 3.2.12 -- Equality as an Inductive Family

Equality is one indexed inductive family with one constructor.

universe u

inductive Eq {α : Sort u} (a : α) : α → Prop where
  | refl : Eq a a

The recursor motive may depend on the second endpoint and the equality proof. Its only method handles refl; therefore eliminating an equality proof reduces the problem to the reflexive case, and Eq.rec ... Eq.refl computes to that method. Equality is shown here only as the classical indexed-family shape; its proof-theoretic use belongs to 2A.

Section 4 -- 结构体类型
Remark 4.1 -- Structures as one-constructor inductive types

A Lean structure is a one-constructor inductive type with named fields. Lean generates its constructor, field projections, record syntax, and recursor. Thus a structure is not a separate foundation beside inductive types; it is a convenient interface for an important special case.

Definition 4.2 -- Point as a named product
structure Point where
  x : Int
  y : Int

Point carries the same data shape as Int × Int, but the projections are named Point.x and Point.y. Its generated constructor is Point.mk.

Definition 4.3 -- DependentPair as a Sigma type
structure DependentPair (α : Type u) (β : α → Type v) where
  fst : α
  snd : β fst

The type of snd depends on the value stored in fst. This is the record presentation of a dependent pair: an ordinary product is recovered when β is constant.

Definition 4.4 -- A type field with dependent operations
structure Automaton where
  State : Type
  start : State
  step : State → Bool → State

A field may itself be a type. Later fields can then depend on it, so one value packages a carrier together with data and operations on that carrier. No typeclass or algebraic laws are involved here.

Definition 4.5 -- A recursive structure with a finite base case
structure LinkedNode (α : Type u) where
  value : α
  next : Option (LinkedNode α)

The recursive occurrence is strictly positive. Although the structure has only one constructor, Option.none supplies a finite stopping case. The lecture constructs a two-node chain with record syntax to make that base case explicit.

Remark 4.6 -- Positive recursion without a finite base case
structure StreamCell (α : Type u) where
  head : α
  tail : StreamCell α

This declaration passes strict positivity, but every constructor application requires another StreamCell. Consequently it has no closed value represented by a finite constructor tree. It should not be confused with a coinductive stream.

Counterexample 4.7 -- Negative recursion is rejected
structure BadStructure (α : Type u) where
  observe : BadStructure α → α

Here the recursive type occurs in a function domain, hence negatively. Lean rejects the declaration before generating a constructor or recursor.
